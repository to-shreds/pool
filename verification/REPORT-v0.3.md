## Completed build

The local release contains 68 operational settings across 12 categories, optional real WebGL cameras, retained 2D/precision placement, dynamic cue-ball equipment and table sizes, shared skill-based execution/risk/chalk, computer opponents and coach, and separate APA-derived match modes. `RELEASE-0.3.md` records the implemented scope and remaining roadmap work.

## Browser-environment boundaries

Administrator policy blocks ordinary file and loopback navigation. Standalone checks therefore initialize the actual bundled HTML with Playwright `page.set_content`. Modular checks fulfill actual local source assets at an intercepted reserved `.invalid` URL. Those are not public-site launch tests.

Successful localStorage tests explicitly use an in-memory shim. The unshimmed blocked-storage warning is tested separately. This does not verify persistence across native browser restarts or transfer between local-file and hosted origins.

Actual graphics checks run headed Chromium under Xvfb with ANGLE SwiftShader. WebGL rendering, picking and visual camera differences were exercised and screenshots inspected, but this is not a physical Android GPU or frame-rate benchmark. Real-device performance, native unrestricted downloaded-file launch and the future Pages URL remain unverified.

## Numerical stress

Seed 843219; **256 attempted and accepted shots**, all settled with finite state. The cases span explicit 7/8/9/custom table sizes and standard, oversized, heavy and custom cue-ball combinations, including 50-64 mm and 120-230 g limits. No case hit the collision-iteration cap or exceeded its initial mechanical energy by more than 0.001 J. Per-case results and diagnostics: `stress-v0.3-results.json`.

A discovered corner-jaw multi-ball jam initially triggered repeated zero-time collisions. It is now covered by an exact regression and a passive slow-contact constraint projection. The separate `contactSettles` diagnostic records that intervention; the collision-cap diagnostic remains enabled. This is a documented numerical approximation, not a claim of experimental ball/rail calibration.

## Other issues caught and fixed

CPU re-entry during UI refresh; stale worker actions after reset/undo; preview/replay state contamination; missing declaration persistence; APA9 cross-rack score handling; overly small compact-phone table region; wood/felt z-fighting in 3D; and legacy-state validation. Failed harness selectors were corrected against the actual UI before counting a passing run, rather than changing production controls to satisfy incorrect tests.

## Publication and remaining scope

At preparation of this report, repository publication and a fresh GitHub checkout/build are still pending; they are not counted above. A separate publication record will identify the verified source commit, file hashes and CI run after completion. GitHub Pages was disabled at the last metadata read. No working live game URL is claimed.

The release is a playable implementation of the major systems, not completion of all calibration goals. Skill/miscue/chalk percentages are model-based, APA rules are explicitly scoped, AI/coach search is bounded with only next-shot positional heuristics, and real-table/pocket/cue obstruction refinements remain. No official APA endorsement, validated skill equivalence or full tournament-referee claim is made.
